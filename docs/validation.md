# Результаты проверки TASK1

Дата: **25 октября 2026 года**.

## Автоматические тесты

В изолированном окружении Python 3.12.14 установлены зависимости из
`requirements-dev.txt`. Выполнено:

```bash
python -m unittest discover -v
```

**34 теста прошли, ошибок нет.** Проверены:

- полный CRUD, 404, отсутствие upsert, валидация и конкурентные создания;
- независимость данных и настроек экземпляров;
- точный набор трёх бизнес-ручек и трёх служебных ручек;
- шаблоны маршрутов вместо ID, фактические HTTP-коды, учёт одного запроса один раз;
- обработанные и необработанные 500, исключение служебных маршрутов;
- динамический каталог, новые бизнес-ручки и префиксы подключённых роутеров;
- отдельные registry и совместимые кумулятивные бакеты двух экземпляров;
- динамическое построение панелей, формулы, селекторы, экранирование путей;
- ошибки Grafana, ограниченные повторы, nonzero exit и проверка сохранённого дашборда;
- расписание ramp-up, отдельные ID-пулы, доля отсутствующих ID;
- ограничения concurrency, сетевые ошибки и конечное число попыток seeding.

После изменения вида легенды ошибок отдельно повторно прошли 12 тестов генератора.

## Реальные проверки конфигураций

Успешно выполнены:

```bash
docker-compose --env-file .env.example config --quiet
promtool check config infra/prometheus/prometheus.yml
```

Использовались официальный standalone Compose CLI 5.6.1 и promtool 3.15.0.
Файлы YAML также разобраны; проверены существование bind mounts, единый образ
приложений, отдельные env, loopback-порты и условия зависимостей.

## Полная связка с работающими процессами

В среде подготовки отсутствует Docker daemon. Поэтому для интеграционной проверки
были запущены реальные native-процессы тех же версий Prometheus 3.15.0 и Grafana
13.2.4, два экземпляра приложения, настоящий CLI-генератор и настоящий нагрузочный
процесс. Grafana и Prometheus получены из официальных дистрибутивов; контрольные
суммы проверены. Временные конфиги отличались от Compose адресами и путями данных.

В этом запуске использовались локальные порты 18001 / 18002, 19090 и 13000.
В поставляемом Compose остаются порты **8001 / 8002, 9090 и 3000**.

Нагрузка работала с обычным 120-секундным ramp-up и настройками проекта.
`scripts/check_stack.py` выполнил **90 реальных запросов панелей** на одной
временной отметке Prometheus, чтобы сравнение агрегаций не зависело от очередного
скрейпа. Результат сохранён в [acceptance-native.json](acceptance-native.json).

| Показатель | Зафиксированное значение |
|---|---|
| Здоровые экземпляры / UP targets | 2 / 2 |
| Бизнес-ручки / панели | 3 / 9 |
| Суммарный RPS, окно 1 минута | 35.4 |
| RPS dc-a | 17.709091 |
| RPS dc-b | 17.690909 |
| RPS при множественном выборе | 35.4 |
| Ошибки 404 | 1.073/с |
| Ошибки 500 | 0.745/с |
| Общая доля ошибок | 5.14% |

Это измерение одного окна, не фиксированная гарантия каждой секунды.
Для каждой ручки проверены сумма отдельных DC и подов, равенство множественного
выбора All, конечность значений и порядок p50 ≤ p95 ≤ p99.

Повторный CLI-запуск завершился с кодом 0: сохранились UID и числовой ID, дашборд
с этим UID остался один. При идентичном содержимом Grafana выполнила no-op без
увеличения версии. `editable: false` сохранён; оба селектора поддерживают Multi / All.

## Визуальная проверка и скринкаст

Дашборд проверен в настоящем Chromium 151: все девять панелей отображают данные,
ошибок JavaScript и `No data` не обнаружено. Проверены оба отдельных датацентра,
отдельные поды, множественный выбор и All. В Prometheus видны два UP target.
Легенда панелей ошибок изменена на список, чтобы подпись HTTP 500 была видна
без внутренней прокрутки.

Скринкаст [demo.mp4](demo.mp4), 60 секунд, 1920×1080, показывает этот реально
работающий native-стенд под нагрузкой. Добавлены русские поясняющие субтитры;
звуковой дорожки нет.
Это запись браузера; графики и статусы не подменялись макетом. Запуск Docker в записи
не демонстрируется. Различие портов с README объясняется временным native-стендом.
