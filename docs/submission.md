# Публикация и сдача TASK1

## Что уже есть в проекте

Реализованы CRUD, библиотека мониторинга, runtime-каталог ручек, генератор
дашборда, нагрузка и запуск через Docker Compose. Есть тесты и проверка
работающего стека. Детали фактической валидации — в `validation.md`.

## Что относится к вашему аккаунту

Для публичного репозитория и PR нужны владелец GitHub, ФИО, группа и трек
(`devops` или `fullstack`). Эти значения не выдуманы и не подставлены за автора.
Файл `PR_BODY.md` подготовлен для заполнения.

Создайте пустой публичный репозиторий в своём аккаунте. Если в каталоге проекта
ещё нет Git-репозитория, выполните:

```bash
git init -b main
git add .
git diff --cached --name-only
```

В списке не должно быть `.env`, виртуальных окружений и runtime-данных.
Установите свои Git author name/email, если они ещё не настроены, затем:

```bash
git commit -m "Implement TASK1 monitoring and dashboard automation"
git remote add origin https://github.com/YOUR_LOGIN/YOUR_REPOSITORY.git
git push -u origin main
```

Не создавайте искусственную историю задним числом. При последующих изменениях
делайте коммиты по реальным этапам. Workflow GitHub Actions запустит проверки
после push; просмотр его результата особенно полезен, если локальный Docker
запуск не был проверен в среде подготовки.

## Проверка перед отправкой

1. Из чистого клона выполните `cp .env.example .env` и `docker compose up`.
2. Через 2–3 минуты проверьте `python3 scripts/check_stack.py --wait 180`.
3. Откройте дашборд: три ручки, p50/p95/p99, RPS и коды ошибок.
4. Проверьте по одному датацентру/поду, несколько значений и All.
5. Убедитесь, что скринкаст доступен проверяющему без запроса доступа.
6. Заполните ФИО, группу, трек и URL в `PR_BODY.md`.

## Сценарий скринкаста на одну минуту

| Время | Демонстрация |
|---|---|
| 0–15 с | Дашборд All: все три ручки, latency, RPS, ошибки |
| 15–30 с | Выбор первого и второго датацентра/пода |
| 30–40 с | Множественный выбор и возврат к All |
| 40–50 с | Prometheus Targets: два доступных экземпляра |
| 50–55 с | `/handlers`: каталог маршрутов |
| 55–60 с | Возврат на дашборд под нагрузкой |

Запись следует начинать после прогрева. Общие вводные фразы не нужны.
Если в комплекте есть `demo.mp4`, это запись фактически работавшего стенда;
способ его запуска указан в `validation.md`.
